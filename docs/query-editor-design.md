# 検索テキストボックスのカーソル操作

検索欄(Mode::Input)にカーソル位置・選択範囲を持たせ、クリックでの位置指定・Home/End移動・部分選択・全選択に対応する。

## 状態

`app.query: String`を、カーソル位置と選択範囲を持つ`QueryEditor`に置き換える。

```rust
struct QueryEditor {
    text: String,
    cursor: usize,       // 文字インデックス(バイトオフセットではない)
    anchor: Option<usize>,  // Some = 選択中。cursorとの間が選択範囲
}
```

文字列操作は`text.chars()`経由で行う(全角文字のバイト境界を意識しなくてよくする)。クエリは短い文字列のため、文字単位での再構築コストは問題にならない。

## 既存呼び出し箇所への影響

`&str`として読むだけの箇所(`ui.rs`の描画、`actions.rs`の検索実行、`category.rs::Tabs::target`)は`QueryEditor`に`text() -> &str`を実装し、そのまま渡せるようにする。全文を置き換える箇所(`actions.rs`のフィードキーワード代入、テストの`app.query = "..."`)は`QueryEditor::set(text)`(カーソルを末尾に、選択を解除)に置き換える。

## キー操作(Mode::Inputのみ、既存キーとの重複なし)

- `Left`/`Right`: カーソルを1文字移動(選択があれば解除してその境界へ)
- `Home`/`End`: カーソルを先頭/末尾へ移動(選択解除)
- `Shift+Left`/`Shift+Right`: 選択を1文字ぶん伸縮(anchorが無ければ現在位置をanchorにする)
- `Shift+Home`/`Shift+End`: 現在位置から先頭/末尾までを選択
- `Ctrl+A`: 全選択(anchor=0, cursor=末尾)
- 通常の文字キー: 選択があればまず選択範囲を削除してからカーソル位置に挿入
- `Backspace`: 選択があれば選択範囲を削除、無ければカーソル直前の1文字を削除
- 既存の`Enter`/`Tab`/`BackTab`/`Esc`/`Ctrl+C`/`Ctrl+S`の扱いは変更しない

## マウス操作

検索欄(`search_areas(screen)[0]`)をクリックすると、その列に対応する文字位置へカーソルを移動し選択を解除する。列→文字位置の変換は`ui::tab_at_column`と同じ「表示幅を累積しながら該当文字を探す」方式を使い、横スクロールの送り幅を足した列で引く。

枠の桁を押したときは、枠の内側の端を押したものとして扱う(左枠なら内側の先頭、右枠なら内側の末尾)。描かれていない文字を指さないよう、列は内側の幅(`area.width - 2`)でクランプする。

## 表示

- `cursor_x`(`ui.rs`)を、クエリ全体でなく「カーソルまでの部分文字列」の表示幅から計算するよう変更する
- 選択範囲がある場合、その範囲を反転表示(既存のREVERSED修飾と同じ扱い)する。反転を出すのは`Mode::Input`のときだけで、結果一覧へ移ったら出さない(カーソルも出ないため)
- クエリが枠の内側に入らないときは横スクロールする。送り幅は「カーソルが内側に入る最小の幅」を文字境界で求めた値で、描画・カーソル桁・クリックの当たり判定が同じ値を使う

## 桁の数え方

表示幅は1文字ずつ`grid::display_width`で積む。カーソル桁・送り幅・クリック位置がすべて同じ積み方を通るので、描画位置とクリック位置が食い違わない。

## 対象外(v1)

- 選択範囲のクリップボードコピー/カット/ペースト(既存の`pbcopy`はURL専用。`pbpaste`相当の読み取りは未実装で新規実装が要るため、今回は含めない)
- ダブルクリックでの単語選択、トリプルクリックでの全選択
- 複数コードポイントで1つの書記素になる文字(ZWJ絵文字、異体字セレクタ)。ratatuiは書記素クラスタ単位で桁を進めるため、文字単位で桁を積むこの方式とは桁がずれる。対応するにはカーソル・選択・幅計算をすべて書記素単位にする必要がある
