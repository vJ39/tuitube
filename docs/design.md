tuitube に手を入れる人向けの説明。使い方は [README](../README.md) にある。ここには、コードを読まないと分からない決まりごとと、実装が前提にしている外部のプログラムの挙動を書く。外部の挙動は mpv 0.41.0・yt-dlp 2026.08.19・curl 8.7.1・iTerm2 3.6.11・macOS 14 で確かめた。

## 全体の構成

外部のプログラムを呼んで動く。検索と一覧・コメント・ダウンロードは yt-dlp、再生は mpv(JSON IPC で操作する)、サムネイルの取得と YouTube Data API の呼び出しは curl、PKCE の SHA-256 は openssl、クリップボードは `pbcopy`、ブラウザは `open`。どれも差し替え口(trait)越しに呼び、テストでは偽物に替える。

`main.rs` のイベントループが、キー・マウス・リサイズと、裏で動く処理の結果(`AppEvent`)を 1 本のチャンネルで受け、`App` を更新して描画する。裏の処理は検索・プレイリスト一覧・チャンネルの引き当て・サムネイル・コメント・OAuth・いいね/登録の状態確認・ダウンロード・mpv の出力の読み取りで、それぞれ `Session` にタスクのハンドルを持つ。新しく始めるときは前のタスクを打ち切り、届いた結果の nonce が今のものと違えば捨てる。nonce は処理ごとに持つが、サムネイル・状態確認・プレイリスト一覧は検索の nonce を共用していて、検索が入れ替わると一緒に古くなる。`cancel_search` はチャンネルの引き当てと OAuth も一緒に打ち切る。

画面(`Mode`)は `Input`・`Results`・`Channel`・`Playlist`・`Playlists`・`Playing`・`Download`・`Settings` の 8 つ。画面ごとの状態・キー処理・描画・テストは `src/screen/` にまとめてある。

- `screen/browse.rs`: 検索欄・結果一覧・チャンネル・プレイリストの中身(検索欄と一覧を持つ画面)
- `screen/playlists.rs`: プレイリストの一覧と、プレイリストを開く・閉じる処理
- `screen/playing.rs`: 再生画面(シークバー・アクション行・コメント)
- `screen/download.rs`・`screen/settings.rs`: ダウンロード画面と設定画面

`input.rs` は `Ctrl+C` と終了の確認だけを受けて残りを各画面へ渡し、`ui.rs` は描画を各画面へ振り分ける。複数の画面で使う操作(検索の開始、再生の開始と終了、サムネイル、OAuth を使う操作)は `actions.rs` にある。`App::view_results` などは、開いているチャンネル・プレイリスト・検索結果のうち今見ている一覧を返す。

ほかのモジュールは機能ごとに分かれていて、先頭の `//!` に役割を書いている。

## 検索と一覧

- 検索は `yt-dlp --flat-playlist --dump-json` で `ytsearch1000:<語>` を読む。実際の件数は `--playlist-end` で絞り、URL の 1000 はページあたりの件数を稼ぐための固定の上限。検索結果ページ(`youtube.com/results?search_query=`)は 1 ページ約 9 件・`ytsearchN:` は 1 ページ約 20 件で、後者の方がページ数が少なく速い(実測: 200 件で 23 ページ 17.1 秒 → 10 ページ 14.9 秒)。`ytsearchN:` の行はチャンネルを含まないが、`ie_key` が `Youtube` の行だけを残す絞り込みは安全側として検索にだけ残している
- 件数は `--playlist-end` で渡す。検索は `[search] limit`、フィードは 30 件(`:ytrec` は制限しないと 167 件返った)、チャンネルのタブとプレイリストは 50 件で、`limit` とは関係しない
- 動画の一覧を取るときは `--extractor-args youtubetab:approximate_date` を付けて `timestamp` を入れさせ、新しい順に安定ソートする。フィードだけは YouTube の並びのまま使う(「後で見る」で足した順が崩れないように)。ショート・ライブのタブと `:ythis`・`:ytsubs` には `timestamp` が入らないので、並びは変わらない
- yt-dlp の出力は終了してからまとめて読む。1000 件の検索では最初の行が出るまで 11 秒かかり、残りはほぼ同時に届いた。このため「もっと見る」は差分を足すのでなく、件数を増やして丸ごと取り直す。増やす量も `limit`、上限は 1000
- 「もっと見る」ができるのは、要求した件数ちょうど返ってきて、まだ上限に届いていない検索のタブだけ(`TabState::requested_limit` で判定する。フィードとチャンネルは立てない)
- 結果を入れ替えるのは `App::set_results` だけで、選んでいた動画が新しい一覧にあればそこを選び直す
- タイムアウトは `[search] timeout_secs`。cookie が効かずに出し直すときは最大 2 回分待つ。進行中の検索は、始めたときの秒数で待つ
- 結果の控え(`[search] cache_enabled`)はメモリだけに持つ。鍵は取得先・件数・cookie を使ったかの組。`cache_ttl_secs` を過ぎた控えは使わない。成功した結果だけを持ち、書くときに期限切れを捨て、それでも 64 件を超える分を古い順に捨てる。`r` は控えを使わない
- タブ(`category.rs`)は「すべて」と設定のカテゴリで、タブごとに結果・選択・スクロール位置を持つ。一度読んだタブは戻っても取り直さない。既定のカテゴリにはフィードの 4 つも入っている
- 起動直後、検索欄が空でも 1 回検索を投げる(`Tabs::startup_index`)。cookie 連携があれば「おすすめ」のタブ、無ければ先頭のカテゴリ。どちらのタブも無い設定なら何もしない
- 検索欄は Enter でも、枠(上下のボーダー)のクリックでも確定できる(`actions::submit_query`)。内側の行のクリックはカーソル移動のまま。どちらも「プレイリストの URL ならその中身を開き、それ以外は検索する」という同じ判定を通る
- 検索欄の文字が動画の URL なら、検索でなく `Target::Video` としてその 1 本を取る。この出力は `ie_key` を持たない 1 行なので、検索の絞り込みは掛からない。1 件届いたときに結果一覧にいてエラーが無ければそのまま再生を始める(設定画面などへ移っていたら始めない)。プレイリストの URL は、一覧から開くときと同じ手順で中身を開く。名前は各行の `playlist_title` から入れる。URL の読み取りは `youtube_url.rs`

## 結果一覧の表示とサムネイル

- 格子(`grid.rs`)は 1 セルが画像・タイトル 1 行・長さと投稿者 1 行。列数は内側の幅 ÷ 16 を 1〜6 に収めた数で、画像は 16:9 を保つ。1 行も入らないときはリスト表示に落とす。計算はすべて整数で、端末には触らない
- 格子の中の移動は端で止まり、リスト表示だけが端で反対側へ回る。末尾で `↓` を押して「もっと見る」を始めるかどうかは、選択を動かす前に判定する(リスト表示では動かした後だと末尾にいたか分からない)
- サムネイルの URL は動画 ID から `https://i.ytimg.com/vi/<id>/mqdefault.jpg`(320×180)を組み立てる。yt-dlp の `thumbnails` の URL は WebP を返すので使わない。ID は `[A-Za-z0-9_-]` だけを受け付ける
- 取得 1 回につき curl を 1 回、`--parallel --parallel-max 6` で起動する。10 枚を 0.14 秒で取れた。キャッシュ済みの ID は渡さない。失敗した ID は、一覧から外れるか寸法が変わるまで取り直さない。curl が無ければ 1 回だけ知らせて以後の取得を止める
- JPEG は `zune-jpeg` で読み、画素数が 1920×1080 を超えるものはヘッダの段階で断る。縮小は面積平均で、端末の寸法が変わったときはキャッシュから読み直す。一時ディレクトリに置いたものとデコードに失敗したものは読んだあと消すので、取り直しになる
- キャッシュは `$XDG_CACHE_HOME/tuitube/thumbs/<id>.jpg`。起動時に更新の新しい順に `max_cached` 枚まで残す。置き場を作れないときは一時ディレクトリに書き、読んだら消す
- 画像は Kitty graphics protocol で自分から送る: カーソルを絶対位置に置いてから `a=T,f=24,s=,v=,C=1,q=2,c=,r=` で送り、4096 バイトごとに分ける。`q=2` は続きのチャンクにも毎回付ける。付けないと端末の応答が標準入力に入り、キー入力として読まれる
- 画像は選択を動かしただけでは貼り直さない。貼り直すのはスクロール・タブ・一覧の入れ替え・リサイズ・画面の出入りのあと(`thumbs.mark_dirty()`)。見ている一覧が変わったかは `view_key()` の変化で判断し、キーでもクリックでも同じ経路でサムネイルを取り直す
- クリックはタブの行、格子のセルの順に判定する。一覧を入れ替えてから描くまでの間のクリックは、世代(`results_generation` と `drawn_generation`)を比べて捨てる
- 印(`badge.rs`)はライブ・ショート・いいね済み・登録済み。ライブは行ごとの `is_live`、ショートはチャンネルのショートのタブを見ている間だけ一律に付ける。格子ではサムネイルの角に小さな画像で、リスト表示では行頭の記号で出す。いいねと登録の印だけが `[engagement] enabled` に従う

## 再生

### mpv の起動

- 起動引数は `display.rs` の `LaunchPlan::args()` が組む。並びは表示の引数、`--speed`、字幕、`--start`(続きから)、`[mpv] extra_args` の順
- `--keep-open` は付けない。再生が終わると mpv が終了し、一覧へ戻る
- mpv の状態は IPC でポーリングする。シークと速度は tuitube が送った値を先に画面へ出し、送ってから 2 秒間は、目標と食い違うポーリング値を古いものとして捨てる(シークは 3 秒以上ずれたら)

### 表示モード

- 表示は `embedded`(Kitty graphics protocol)→ `text`(文字ブロック)→ `window`(別ウィンドウ)の順に `w` で回る。切り替えは mpv を起動し直さず、`set_property vo` で行う。切り替えに成功したら設定ファイルの `display.mode` の 1 行だけを書き換える
- `current-vo` を毎秒聞き、求めた表示と違う間は状態行に「(切替中)」を出す
- `embedded`: mpv の `--vo=kitty` が標準出力へ出す画像を読み、tuitube が位置を決めて端末へ書く。フレームは映像の領域に合わせて `c=`・`r=` で端末側に拡大させる。寸法を変えるときは `vo-kitty-*` を書き換えるだけでは効かないので、書き換えてから `vid no` → `vid auto` で出力を作り直す。固定で `left=1`・`top=1`・`alt-screen=no`・`config-clear=no` を渡す。`--vo-kitty-use-shm` は使わない(共有メモリで送ると終わりの印が来ず、フレームが組み上がらない)
- 画像を消すときは `a=d,q=2` を送る。描画の順は映像が先でサムネイルが後(再生の終わりに送る消去が、直後に貼るサムネイルを消さないように)。終了時は代替画面を抜ける前に消す
- `text`: mpv の `--vo=tct` の出力を仮想端末(`tct.rs`)で読む。tct は 0 始まりの位置指定を出すので、1 を足して書き直す。文字セルの数がそのまま解像度になり、画質の設定は効かない
- `window`: `--vo` を渡さず mpv に選ばせる(`[window] vo` を書けば固定できる)。`fullscreen` などの `[window]` の値は起動時の引数にだけ効き、`w` の切り替えには効かない。別ウィンドウの間は端末のリサイズを mpv へ送らず、端末内の表示へ戻すときに送り直す
- 画質(`quality`)は端末へ送るフレームの画素数の上限で、`max_frame_pixels` が優先する。mpv のデコードの負荷は変わらない
- fps の上限は起動時に `--vf-append` のフィルタで付ける。埋め込みと文字ブロックに効き、別ウィンドウへ移るときに外し、戻るときに付け直す。既定 15 は、制限なしだと mpv の CPU 使用率が 122% だったのが 40% になった値
- 端末が画素の寸法を返さないときは、1 セルを 8×16 画素とみなす
- コメントを出している間は映像の領域をコメントが使う。届いたフレームは捨てずに持ち、閉じたときに貼り直す

### 裏での再生

- 再生画面の `b` で一覧へ戻っても mpv は止めない。端末内の表示では一覧の右上に小さな映像を重ねる。大きさは画像のとき 32×10 セル、文字ブロックのとき 64×18 セル(文字ブロックはセルの数が解像度なので広く取る)
- 別ウィンドウで再生しているときも `b` で一覧へ戻れる。映像は重ねず、mpv のウィンドウで再生が続く

### シークバー

- シークバー(`seekbar.rs`)は自前の Widget で描く。右端のラベルの幅は動画の長さだけで決め、長さが分からない間は 19 桁取る
- クリックとドラッグは離したときに 1 回だけ絶対シークを送る。送る前に 0 から「長さ − 1 秒」の間に収める。mpv の絶対シークは負の値を末尾からの位置として扱い、長さちょうどへ飛ぶと(`--keep-open` が無いので)終了するため
- ドラッグ中に端末の外で離すと離した合図が届かない。次にボタンを押していない移動が届いたら、ドラッグを取り消してシークしない
- crossterm のマウスは移動も届く(`?1003h`)。種類の分からない離す合図は左ボタンとして届くので、左ボタンだけを見る
- アクション行(いいね・登録・保存)の押下はシークバーより先に判定する。移動はアクション行で止めない(シークバーのポインタ表示が動かなくなるため)

### 倍速

- 速度は `Speed(u8)` に 0.1 倍単位の整数で持つ(1〜40)。端で止まり、値が変わらないときは送らない
- mpv の `speed` は 0.01〜100 を受け付ける。mpv のウィンドウの `]` は 1.1 倍ずつ変えるので 2.75 のような値になることがある。ポーリングで 0.1 刻みに丸めて取り込み、範囲の外なら丸めた値を送り返す
- 速度は `App` に持って次の動画へ引き継ぐ。1 倍のときは `--speed` を付けない

### 字幕

- `[subtitles] enabled` が true のとき、起動引数に `--ytdl-raw-options-append=write-auto-subs=`・`--ytdl-raw-options-append=sub-langs=<lang>`・`--slang=<lang>`・`--sub-visibility=yes` を渡し、消した状態で始めるときだけ `--sid=no` を足す
- `write-auto-subs` は必ず `sub-langs` と組で渡す。単独だと ytdl_hook の既定の `--sub-langs all` が残り、字幕のトラックが 157 本になった。`--ytdl-raw-options-append` の値は `,` で分けられないので、`lang` はカンマ区切りのまま 1 つに入れる
- `lang` は言語コードのカンマ区切りだけを受け付ける(`all` は断る)。同じ値を `--slang` にも渡すので、yt-dlp だけが分かる書き方は使えない
- 出す・消すは `set_property sid auto` と `sid no` だけで行う。`--slang` を起動時に渡しておけば `auto` で同じ言語に戻る。番号の `sid` は無いトラックでも成功が返って黙って外れるので使わない
- 実際に選ばれた言語は `current-tracks/sub/lang` で聞く。`--slang` の先頭が選ばれるとは限らない
- 字幕が無いと判断するのは、求めてから 3 秒たち、かつ長さが取れてから 3 秒たったとき。長さが来ないライブなどは 20 秒で打ち切る。`sid` の問い合わせが値を返さなかった回は前の状態を保つ
- 出すかどうかの希望は次の動画へ引き継ぎ、選ばれていたトラックは引き継がない
- 文字ブロックの表示では mpv が字幕を描かない(埋め込みでは `sid` の有無で出力が変わり、tct では同じだった)。この表示で字幕を出したときは、出ないことを知らせる

### 続きからの再生

- 動画が終わる・次の動画に替わる・終了するときにだけ位置を記録する(再生中に定期的には書かない)
- 95% 以上見たか 60 秒未満の動画は記録を消し、10 秒以降でやめたときに記録する。記録は 500 件までで、古く更新されたものから捨てる
- `resume.toml` は読み直してから丸ごと書き直す。プロセスごとに名前の違う一時ファイルへ書いてから `rename` する

### コメントと URL のコピー

- コメントは `yt-dlp -J --write-comments` で、いいねの多い順に 50 件を取る。15 秒で打ち切る。コメントを閉じた動画は `comments` が無いので、空の一覧として扱う
- 結果は動画ごとの世代で受け、入れ替わった後に届いたものは捨てる
- URL のコピーは `pbcopy` へ書く。2 秒で打ち切る

## ログイン連携(cookie)

- cookie の渡し方は `CookieSource` のブラウザ指定(`--cookies-from-browser`)か cookies.txt(`--cookies`)。両方あれば cookies.txt を使う。環境変数 `TUITUBE_COOKIES_FROM_BROWSER` はどちらも上書きする
- cookies.txt は読めることに加えて、追記で開けることも起動時に確かめる。yt-dlp が終了時に書き戻すため
- 状態は `Off`・`Armed`・`Active`・`Suspended`。読めない・復号できない・`Armed` の間のタイムアウトのどれかで `Suspended` にし、その起動中は戻さない。cookie 無しで出し直すのは読めなかったときだけ
- mpv に cookie を渡すのは `Active` になってから(検索で効くと確かめてから)。`--ytdl-raw-options-append` で足す
- cookies.txt が使えないときは、ブラウザ指定があってもそれは使わず、連携なしで起動する
- yt-dlp の失敗の見分け方(`cookies.rs`):
  - 対応ブラウザは brave・chrome・chromium・edge・firefox・opera・safari・vivaldi・whale。それ以外は `unsupported browser` で終了コード 2、入っていないブラウザは 1
  - キーチェーンで復号を断られると、終了コード 0 のまま WARNING だけを出す。成功に見えるので、この出力を最初に調べる
  - Safari の cookie は保護された場所にあり、端末アプリにフルディスクアクセスが無いと `Operation not permitted` で断られる(確認のダイアログは出ない)。このときだけ案内を出す
- フィード(`:ytrec`・`:ythis`/`:ythistory`・`:ytsubs`・`:ytwatchlater`)は cookie が無いと取りに行かずに断る。`:ytrec` は未ログインでもエラーにならず 0 件で返るため
- `:ythis` の行には投稿者が入らない
- 1 つのプレイリストの中身は公開のものなら cookie 無しでも取れるので、先に断らない
- 検索の控えの鍵には cookie を使ったかが入る

## OAuth(いいね・登録・保存)

- PKCE の OAuth 2.0(インストール型アプリ)。curl・openssl・`open` とローカルの TCP だけで実装していて、HTTP のクレートは使わない
- ブラウザからの戻り先は `http://127.0.0.1:<port>/callback`。空いているポートで待ち、300 秒で待つのをやめる。`access_type=offline` と `prompt=consent` で毎回 refresh token を受け取る
- 秘密の値(クライアントのシークレット・refresh token・認可コード)は curl の引数に置かず、`--config -` で標準入力から渡す(`ps` で見えないように)。クライアントのファイルが壊れていても、中身をエラーに出さない
- refresh token は `oauth_token.toml` に権限 600 で保存する(作るときからそのモードで作る)。access token は保存せず、操作のたびに取り直す
- curl がつながらなかったときも `-w` の書式は出力され、HTTP のステータスが `000` になる。ステータス 0 と curl の失敗(つながらない 7、時間切れ 28)は通信の失敗として扱う
- 既に登録・いいね済みで返る重複のエラーは成功として扱う
- 「後で見る」には `playlistItems.insert` が使えない(`400 playlistOperationUnsupported`)。代わりに名前がちょうど「tuitube」のプレイリストを探し、無ければ非公開で作って足す。作った直後に中身を問い合わせると見つからないと返るので、作ったときは重複を確かめずに足す。割り当ては 1 回の保存で 52、作るときは 101(自分のプレイリストの一覧が 2 ページ以上あれば、1 ページごとに 1 増える)
- 使うスコープは `youtube.force-ssl` だけ
- 裏での状態確認はブラウザを開かない。保存済みの refresh token があるときだけ問い合わせる

### いいね済み・登録済みの控え

- `videos.list` の `myRating` は `id` と一緒に使えないので、1 本ずつ「いいね済みか」を聞けない。いいねした動画の一覧を丸ごと取る(1 ページ 50 件、20 ページ = 1000 件で打ち切り。ページは前のページのトークンが要るので順に取る)
- 登録済みかは、表示中のチャンネルを 50 件ずつにまとめて聞き、`[engagement] max_concurrent_requests` 本まで並べて投げる。1 つでも失敗したら全体を失敗とし、聞けなかったチャンネルを未登録と決めつけない
- 控え(`engagement.rs`)は問い合わせの結果と、tuitube でした操作をためるだけで、自分からは問い合わせない。`ttl_secs` を過ぎたものを取り直す。時計が戻って未来の確認時刻が残っていても期限切れとして扱う
- チャンネルの控えは 500 件まで。いいねの一覧を一度も取っていないうちに tuitube でいいねしても、一覧の確認時刻は進めない(進めると最初の取得が期限まで止まる)
- 登録状態が分からないチャンネルは未登録と同じ見た目にする
- `engagement.json` は `<名前>.tmp.<pid>` に書いてから `rename` する。控えが空なら書かない
- 再生画面の登録(`u`)は、再生を始めたときの行の `channel_id` を使う。`channel_id` の無い行から始めた再生では登録できない
- 結果一覧・チャンネル・プレイリストの中身では、`l`(いいね)・`u`(登録)を選んでいる行に対して使う。`u` は行が `channel_id` を持つ場合だけ効く(`actions::like_video` は `App::view_selected_result()` を見る。`actions::subscribe_selected_channel` は行の `channel_id` を使うので、チャンネルタブの行(`channel_id` を欠く)では効かない。そちらは `subscribe_channel` が `app.channel.channel_id` を使う)

## チャンネル

- チャンネルは `https://www.youtube.com/channel/<id>/{videos|shorts|streams}` を 3 つのタブとして持ち、それぞれ 50 件まで読む。読んでいないタブだけを取りに行く
- `c` を押した行が `channel_id` を持っていなければ、その動画 1 本をフラットでなく取り直してチャンネルを引く。引き終わったとき、選択中の行の `video_id` と一致し、まだ結果一覧・チャンネル・プレイリストの中身にいれば開く
- チャンネル名は、引いた行の投稿者、選択中の行の投稿者、チャンネル ID の順で決める
- ライブ配信のタブが無いチャンネルでは、`/streams` の「そのタブは無い」という失敗だけを 0 件として扱う
- `/` は開く前の画面へ 1 段だけ戻る(`leave_channel`)。`Esc` はネストの深さに関わらず検索欄まで直接戻る(`actions::jump_to_search`。チャンネル・プレイリストの中身・プレイリスト一覧を全部畳んでから `Mode::Input` にする)

## プレイリスト

- 一覧は `https://www.youtube.com/feed/playlists` を読み、ID と名前だけを持つ。中身は `Target::Playlist` として検索と同じ経路で読む
- `app.playlists`(一覧)と `app.playlist`(中身)を別に持つ。中身から戻るときは、一覧があれば一覧へ、無ければ(URL で開いたとき)検索側へ戻る
- `/` は 1 段だけ戻る(中身→一覧→検索側の順)。`Esc` はどちらの画面からも `jump_to_search` で検索欄まで直接戻る
- 一覧と中身の画面ではマウスを使わない

## ダウンロード

- `yt-dlp -f bestvideo+bestaudio/best -o <保存先>/<ファイル名>.%(ext)s --print after_move:filepath <URL>`。音声は `-f` の代わりに `-x --audio-format mp3`
- ファイル名はタイトルの `/` と `\` を `_` にしたもの。`-o` は yt-dlp の書式として読まれるので、保存先とファイル名の `%` は `%%` にして、打ったとおりの名前で保存する
- 同時に 1 本だけ。新しく始めると前のものを打ち切る。保存先かファイル名が空なら始めない
- 失敗の理由は、出力の中で `ERROR` を含む最初の行、無ければ最後の空でない行を出す
- `[download] debug` が true のときだけ、引数・終了コード・出力を `download-debug.log` に追記する

## 設定

- 設定ファイルは起動時に 1 回だけ読む。キーはすべて任意で、知らないキーは無視する。選択肢のキーは文字列で受けてから検証する(enum で受けると 1 つの誤りでファイル全体が読めなくなるため)。範囲の外の値は丸めて、起動時に知らせる
- 雛形は `settings::render` が作る。README の設定ファイルの例はこの出力と同じで、テスト(`the_readme_shows_the_template_tuitube_writes`)が確かめる。項目を足したら README も直す
- `w` と `v` での切り替えは該当の 1 行だけを書き換え、書き換えた後に読み直して値を確かめる。行を見つけられないとき(dotted key など)は保存しない。設定画面での保存はファイル全体を作り直すので、コメントと知らないキーは消える
- 環境変数で上書きしている値は、保存するときにファイルにあった値へ戻して書く
- 設定画面に出すのは `SETTINGS_ITEMS` の 14 項目だけ。自由な文字列の項目のほか、`[engagement]`・`display.max_frame_pixels`・`window.fullscreen` なども出さない

## 非表示

- `hidden.toml` の `videos` と `channels` を動画 ID とチャンネル ID で照らす。動画の `title` は表示用。チャンネルの `title` は名前での照合に使う
- フィードとチャンネルのタブの行は `channel_id` を持たないので、どの行も、投稿者の名前が隠したチャンネルの名前と同じなら隠す。同じ名前の別のチャンネルも隠れる
- 隠した行は `set_results` で入れる前に落とす。落とす前の件数を `TabState::fetched` に持ち、「もっと見る」の判定と次に頼む件数はこちらで決める(隠した分で止まらないように)
- 追記は 1 件ずつ、ファイルを読み直してから足す。読めないファイルには書かない。一時ファイルに書いてから `rename` する
- 隠したらその場で今の一覧からも外す。結果一覧が空になったら検索欄へ戻る。チャンネル画面の `h` はそのチャンネルごと隠して検索側へ戻る

## テスト

外部のプログラムは差し替え口の向こうにあり、テストでは偽物を使う: `FakeYtDlp`(`search.rs`)・`FakeCurl`(`fetch.rs`)・`FakeBackend`(`oauth.rs`)・`FakeClipboard`(`clipboard.rs`)・`FakeDownloader`(`download.rs`)・mpv への送信を記録する `Recorder`。設定などのファイルは、パスを受け取る `_from`/`_to` の側を一時ディレクトリでテストする。

単体テストで動かさないのは次の部分で、手元で実際に動かして確かめる。

- mpv の起動と IPC
- OAuth の実際の通信とブラウザからの戻り
- クリップボードへの書き込み
- 端末の初期化とイベントループ
- 環境変数から実際のパスを決める入口(`settings::load` など)
- 本物の実行者を渡すだけの入口
