# 結果一覧の末尾での自動読み込み

`m`キー(#52)に加えて、結果一覧の末尾で`↓`キーを押したときも「もっと見る」が動くようにする。特別なキーを覚えなくても、末尾まで送れば自然に続きが出てくる体験にする。

## 対象

Resultsモードの`↓`キーのみ。`m`キーと同じスコープ(`Target::Search`のタブでだけ動く)に揃える。Channelモードは対象外(`m`キー自体がChannelモードに無いのと同じ理由)。

## 判定

`↓`を押した時点で、押す**前**の選択位置が一覧の最後の行(`view_selected() + 1 == view_results().len()`)であり、かつ`can_load_more()`が真で、かつ`app.searching`が偽(取得中の多重発行を防ぐ)なら、選択は動かさず`load_more`を呼ぶ。それ以外は今までどおり`move_selection(Dir::Down)`を呼ぶ。

判定を選択を動かす**前**に行う理由: list表示の`select_next`は末尾で先頭へ巻き戻る(既存の周回ナビゲーション)。動かした後に判定すると、末尾にいたことが分からなくなる(選択が0に戻ってしまっている)。判定を先にすることで、grid表示(末尾で止まる)とlist表示(末尾で巻き戻る)のどちらでも同じ基準で捉えられる。

もっと見られない(`can_load_more()`が偽。既に上限まで取った・まだ一度も検索していない・Feed/Channelのタブ等)ときは今までの動きのまま変えない。list表示の周回ナビゲーションもそのまま残る。

取得中(`app.searching`)に末尾で`↓`を押し続けても、`load_more`を呼び直さない(結果がまだ入れ替わっていないので同じ要求件数になり、取り直しても意味がない)。取得が終わって一覧が入れ替われば、新しい末尾に着くまでは普通に移動できる。

## 実装箇所

- `src/app.rs`: `App::view_is_at_last_result() -> bool`(`view_selected() + 1 == view_results().len()`、0件なら偽)
- `src/input.rs`: `handle_key_results`の`KeyCode::Down`を、上の判定で`load_more`呼び出しと`move_selection`呼び出しに振り分ける

## 対象外(v1)

- マウスホイールでの末尾検知
- Channelモードでの同様の自動読み込み
- `↑`キー(先頭)での対応する挙動
